# 双服务器程序备份与版本管理防回退记录

修复范围仅为管理端版本管理：推送、进度、提交历史和独立程序快照服务。

- 生产运行仓库 HEAD 与 GitHub coin 分叉，旧推送直接提交运行仓库，导致非快进失败。新流程从 GitHub 当前 coin 创建子提交，不操作运行仓库 HEAD、索引、分支或合并状态。
- 业务服务器同时缺少 GitHub 写入凭据。已配置仅授权目标仓库的部署密钥，通过 GitHub HTTPS 元数据固定 SSH 主机指纹；账户级令牌不保存到生产服务器，密钥不进入备份。
- 原 Rust 同步只采集源码，遗漏实际运行二进制。现分别采集 18.176.76.127 与 57.181.214.206 的当前项目源码及程序，并通过 /proc/PID/exe 读取运行引擎。
- 两个域名的 static、dist、public、旧新资源、提示音、外部 nginx LOGO 均保留；逐文件 SHA256 校验并提供主机清单和可重组归档分片。任何一端缺失或校验失败不得报告成功。
- 不启动 PostgreSQL 备份或轮换，不包含数据库、行情数据、密钥、会话、依赖和构建缓存。
- 默认备注来自 deploy/latest-repair-summary.txt；后台任务跨页面继续执行，重复点击复用任务。进度由采集、校验、GitHub 推送与确认阶段驱动，失败不显示完成。
- 历史从独立 Git 镜像读取 GitHub coin；成功 SHA 必须在刷新后的列表中确认。错误保留旧列表并允许重试。
- 生产管理端源码落后于正在服务的构建。此次不整站重建，只替换 VersionTab，其他关联资源只更新 import URL，并逐字节核对。新增资源后最后原子切换 HTML，禁止删除现有 dist/static 文件。

验证：Linux 隔离 Git 测试 17 项通过，覆盖分叉运行仓库保护、远端并发提交、历史缓存失效、任务互斥、归档损坏/缺件/分片重组等；管理端 TypeScript 检查及 8 项浏览器模拟场景通过。生产双主机试采集逐文件校验通过。真实推送结果以 GitHub coin 提交和 backup-status 的 git_commit 为准。
